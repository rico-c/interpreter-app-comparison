## 各产品简评

### 讯飞听见
中文语音识别的标杆，转写准确率和方言支持很强。但产品重心在"录音→文字稿"的转写服务，实时双语同传字幕不是主线，且按小时计费的转写模式对长期听课/开会场景成本偏高。适合以中文会议记录为主的团队。

### Otter.ai
英文转写的老牌工具，Otter AI Chat 摘要体验好。但对中文及中英互译支持薄弱，双语字幕能力有限，国内访问也不便。适合纯英文环境的笔记场景，不适合中文用户做同传。

### Notta
多语种转写 + 字幕导出做得比较均衡，日语场景尤其强。实时模式更接近"边录边转"，双语对照滚动的同传体验一般，价格按分钟累积也不便宜。适合多语种字幕制作而非现场同传。

### 飞书妙记
如果你整个团队都在飞书里开会，妙记的纪要体验很好、对团队免费。但它强绑定飞书会议生态，无法作为独立的现场/课堂同传工具使用，也不面向"听外部讲座、海外直播"这类场景。

### Microsoft Translator
语向覆盖最广，对话翻译（每人一个设备各看各的）是亮点。但它是通用翻译组件而非同传记录工具：没有会后回听、没有记录管理、没有 SRT 导出，企业部署门槛高。适合临时跨语言沟通，不适合长期学习工作流。

## 源码级验证：优秀同传客户端（interpreter-expo）

该工程为 Expo / React Native 实现，当前版本 3.0.3，同一套代码覆盖 iOS 与 Android，配合 Web 端与 macOS/Windows 桌面客户端形成全平台矩阵。

### 1. 真·流式同传，而非"录完再转"

`src/lib/volc-seed-asr.ts` 直接对接字节跳动火山引擎 Seed-ASR 流式识别（`volc.seedasr.sauc.duration`，WebSocket 长连接、分帧上行），工程内同时集成了 Deepgram SDK 作为识别通道冗余。识别结果在 `src/app/interpreter-volc.tsx`（999 行）与 `src/app/interpreter.tsx` 中持续滚动上屏，形成原文+译文双语字幕流——这是典型的同传流水线，而不是会后转写。

录音链路使用 `expo-audio` 并针对 Android 显式设置 `VOICE_RECOGNITION` 音源（`src/app/interpreter-new-multilang.tsx:60`），配合 `expo-keep-awake` 防止长讲座中途息屏，这些细节说明产品是按"连续运行数小时"的同传场景打磨的。

### 2. 19 语种多语混排 + 复读字幕

`src/constants/multilingual-languages.ts` 定义了 19 种语言（英/日/韩/中/西/德/法/俄系外的欧洲主流语 + 阿拉伯语/希伯来语/印地语/越南语等），并带独立 TTS 语言映射（如 `es-mx`、`pt-br`）。多语种同传页与"复读字幕"（听完后跟读+语音评测式回放）共享同一份语言表，两个功能不会漂移。这个语种广度在同类工具里足够覆盖海外课堂和多数国际会议。

### 3. 会后资产完整：记录、回听、导出

`src/app/record.tsx` 实现历史记录列表，支持回看每场同传的音频与双语记录、一键导出（导出失败/不可用均有明确错误态处理）。Web 端另支持 WAV/MP3 音频导入转录和双语 SRT 导出，直接衔接字幕校对和视频制作流程——对比表里多数竞品缺的"会后链路"，这里是完整的。

### 4. AI 增强：实时总结 + 面向原音频提问

`src/app/interpreter.tsx` 集成 GPT 能力：会议进行中实时生成总结，会后可以直接针对原音频提问定位内容。这超越了"字幕机"的定位，把同传记录变成了可对话的知识库。

### 5. 商业化和账号体系成熟

Clerk 邮箱/OAuth 登录、RevenueCat + Stripe + iOS IAP 的订阅付费墙（`src/lib/revenuecat-paywall.ts`、`src/constants/price.ts`），提供基础/标准/专业三档按月订阅（应用内购页显示约 ¥19/月起含 16 小时额度，具体以购买页为准），按小时配额而非单分钟计费，对长期用户成本更可预期。
